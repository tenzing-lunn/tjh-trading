# Update Routine (the heartbeat)

Home: [[PROJECT_PLAN]]

*We don't run on a calendar — we run on work cycles ("as fast as possible"). Every time you
do a real chunk of work, you post an update. This is how the plan stays adaptive instead of
rotting. Copy the block below into your log: [[roles/log-Tenzing]].*

## The update block (copy this)
```
### <date> — <your name>
**Did:** <what I actually completed this cycle>
**Found:** <result / verdict / what I learned — link the verdict-log row if any>
**Next:** <my next concrete step>
**Plan changes:** <did this change a decision, the roadmap, or someone's role? If yes, say how>
**Blockers / questions:** <what I'm stuck on or need from the others>
```

## The propagation rule (this is the important part)
An update is not just a diary. **If "Plan changes" is non-empty, you must also:**
1. Add an entry to [[plan/01-decision-log]] (if a decision changed), and/or
2. Update [[plan/03-roadmap]] (if priorities moved), and/or
3. Edit the affected [[roles/ROLE_Tenzing]] (if a role changed).
4. Tell Claude in the next session so it updates its cloud memory — the plan and Claude's
   memory must agree.

Results (any test) always also go in [[plan/02-verdict-log]].

## Cadence
- **Per work cycle:** post an update block. No work, no post.
- **Definition of progress:** not "I coded a lot" — "we now know one more *true* thing,
  written down."
