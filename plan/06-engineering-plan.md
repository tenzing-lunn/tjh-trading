# 06 — Tenzing Engineering Plan

Home: [[PROJECT_PLAN]] · Owner: **Tenzing** · Scope: coding / engineering

*This is the builder roadmap. The next 1-2 months optimize for one external artifact: a
deployed web app that makes the backtest harness visible, honest, and portfolio-worthy.
The larger system ideas live here too, but they are parked until the app ships.*

## North star
Ship a deployed, portfolio-quality web app powered by the canonical Python harness. The app
is the artifact people can understand; the Python engine is the truth source. Do not
reimplement the backtest in JavaScript. Do not let future platform ideas distract from the
first deployed version.

**Done means:** a stranger opens a public URL and, in under a minute, sees one strategy look
good frictionless and die after costs + out-of-sample — without us explaining it.

## 1-2 month build plan

### Phase 0 — Clean the ground   ✅ Done (2026-06-29)
Goal: prevent fake results before building UI.

- Keep conceptual notes such as [[Quant Pipeline]] as notes, not source-of-truth logic.
- Clean `realdata/nio.csv` and `realdata/sofi.csv` so pre-IPO flat/zero-volume rows cannot
  produce fake edges.
- Remove or clearly quarantine mock/throwaway Kronos outputs, especially
  `realdata/tqqq.kronos.csv` if it is not a real model run.
- Add a simple dependency/setup story so another person can run the harness.
- Add basic sanity checks for no-lookahead, cost erosion, and walk-forward boundaries.

Deliverable: the repo is trustworthy enough to build on.
**Verify:** a one-command sanity script exits non-zero if (a) `kappa=0` shows a frictionless
edge (would mean lookahead leaked in), (b) net return ever exceeds gross, or (c) a fold's
test window overlaps its train window. Green = safe to build UI on top.

### Phase 1 — Python results export   ✅ Done (2026-06-29) — `export_results.py`
Goal: make the web app consume truth without duplicating strategy math.

Build one command that exports web-ready results from the existing harness:

- ticker metadata and date range
- price series
- strategy positions
- trade markers
- gross and net equity curves
- cost-regime metrics
- out-of-sample walk-forward metrics
- data-quality warnings
- strategy metadata and plain-English descriptions

Deliverable: a reproducible `results.json` generated by canonical Python code.
**Verify:** re-running the export on the same inputs is byte-stable; every metric in the JSON
matches what `run.py` prints for the same ticker; no strategy math lives anywhere but the
`.py` files (the exporter only reads and serializes).

### Phase 2 — Deployed web app v1   🟢 Built locally (2026-06-29), deploy pending
Goal: ship the clear visual artifact.

*Architecture (chosen 2026-06-29, see [[plan/01-decision-log]]): Next.js front end +
`api_server.py` (FastAPI) that runs the harness on demand, so users pick any ticker and tweak
costs live. Reuses the `export_results` code path so the app can't drift from the CLI. Built,
type-checked, prod-build-passing, verified against the live API; deploy steps in
`webapp/README.md`.*

Core screens:

- ticker picker
- strategy picker
- actual price chart
- long/flat/short signal overlay
- trade markers
- equity curve: strategy net of costs vs buy-and-hold
- verdict panel: OOS return, Sharpe, max drawdown, trades, win rate
- cost comparison showing frictionless vs realistic costs

Deliverable: a deployed app that makes the lesson visible: a pretty signal is not real if
costs and out-of-sample testing kill it.
**Verify:** the app loads from a public URL on a phone; the displayed verdict numbers match
`results.json` exactly; the frictionless-vs-realistic gap is visible without reading docs.

### Phase 3 — Make it interview-strong
Goal: turn the app from a chart into an engineering story.

- Write a polished README with architecture and demo flow.
- Explain no-lookahead clearly.
- Explain out-of-sample walk-forward clearly.
- Include a demo script: "watch a strategy look good before costs and fail after costs."
- Keep sample data/results public-safe and reproducible. **Do not commit raw Yahoo/yfinance
  CSVs to a public repo** — redistribution is restricted. Ship either the synthetic fixture or
  a derived/aggregated `results.json`, and keep `realdata/*.csv` gitignored.
- Add a short future-roadmap section that shows system-design judgment without promising too
  much.

Deliverable: a project that can be shown in interviews, club meetings, and portfolio reviews.
**Verify:** a clean clone + documented commands reproduces the deployed result from scratch;
no private or license-restricted data is in the public history.

## Inputs feeding the engineering system

These feed the engineering system without blocking the first deployed app.

### Strategy inputs
- Written strategy theses from [[research/_thesis-template]].
- Pre-registered expectation before each run.
- Plain-English sizing and risk rules.
- The economic reason the edge should exist.

Tenzing turns accepted theses into signal functions and visible app scenarios.

### Reality inputs
- Cost assumptions by instrument.
- Tradable-universe rules.
- Benchmark selection and same-window comparison.
- Verdict-log entries comparing strategies against buy-and-hold / SPY.

Tenzing turns these assumptions into cost regimes, warnings, and verdict panels.

## Guardrails
- Python produces truth; the web app displays it.
- Every displayed verdict must be net of `costs.py`.
- Every tunable strategy needs an OOS walk-forward result.
- Frictionless results are diagnostic only.
- No order execution or money movement belongs in this app.
- Future platform ideas are allowed in this document, not in the v1 scope.
